## 1 · 계층을 프로덕션 인덱싱에 붙이기

- [ ] `derived` 모드로 전체 코퍼스를 한 번 인덱싱해 계층 엣지가 검색 결과를 어떻게
      바꾸는지 측정한다. 지금은 데모에서만 돌려 봤다.
- [ ] 페이지당 호출 비용과 지연을 근거로 기본값을 `off`로 둘지, 포맷·크기 기준으로
      켤지 정한다. 판독 수(`GRAPHME_HIERARCHY_READINGS`)도 같은 저울에 올린다 — 2면
      호출이 배로 들고, 갈린 페이지에서만 한 번 더 든다.
- [ ] 판독이 갈린 자리를 기록할지 정한다. 지금은 어느 판독을 왜 택했는지가 로그에만
      남고 그래프에는 남지 않는다.
- [ ] 흐름 문서의 페이지 넘김 규칙을 더 긴 문서에서 확인한다. 지금은 예산 1,200 토큰 안에서
      열린 사슬 → 제목 골격(예산의 절반까지) → 최근 절 통째로를 넘기고 하단 30% 이미지를 함께
      보낸다 — 수십 페이지짜리에서 골격이 예산을 넘을 때 깊은 제목부터 빠지는 것이 괜찮은지 본다.
- [ ] 텍스트 묶기를 DOCX에도 쓸지 정한다. 지금은 PDF·PPTX만(`GROUPING_FORMATS`) — DOCX는
      파일이 문단을 통째로 주므로 필요 없다고 봤지만, 텍스트 상자로 쪼개진 제목은 확인하지 않았다.
- [ ] 작은 글씨 규칙(본문 최빈 크기와의 차이, 위아래 본문 유무)과 한 호출 조각 수를 더 많은
      문서 종류에서 확인한다. 논문과 한국어 보고서 두 종류로만 맞춰 본 규칙이다.
- [ ] 쪼개진 표의 틀 안 텍스트 흡수를 그림 묶기가 표를 묶지 않은 경우에도 할지 정한다. 지금은
      페이지가 한 표라고 말했을 때만 흡수한다.
- [ ] 페이지를 걸친 표를 두 페이지에 나눠 크롭할지 정한다. 지금은 더 많이 보이는 쪽에서
      한 번만 자르므로 반대쪽 조각은 크롭에 없다.
- [ ] PDF에도 문장 앞 공백을 셀지 정한다. 지금 `indent`는 DOCX만 두 방식(문단 설정과 앞
      공백)을 세고, PDF는 블록의 왼쪽 좌표만 쓴다.
- [ ] 프레임 판정 임계값(면적 15%·채움 50%·최장 셀 200자)을 다른 PDF에서 확인한다. 지금은
      두 문서로만 맞춰 본 값이다.
- [ ] Neo4j 내보내기를 실제 인스턴스에 적재해 확인한다. 지금은 스크립트·레코드의 모양까지만
      검증했다(로컬에 Neo4j가 없다). 최상위 유닛에도 페이지 루트로부터 `OUTLINE_PARENT`를 둬서
      계층 관계만으로 완결된 트리가 되게 할지도 같이 정한다.

## 1.5 · 검색과 웹 앱

- [ ] 문서번호와 "문서·요약" 같은 흔한 단어를 함께 쓴 질문에서 그 번호의 문서가 상위에서 밀린다.
      번호가 있으면 전문 검색 쪽 가중치가 커지는데, 흔한 단어가 다른 문서의 구절과 맞는다. 번호가
      일치하는 문서를 올려 줄지, 흔한 단어를 전문 쿼리에서 뺄지 정한다.
- [ ] 한 문서가 1차 결과를 독차지하는 경우가 있다. 문서당 구절 수를 제한할지 정한다.
- [ ] RRF `k`(60)와 가중치(0.6), 기준선(0.3)을 실제 질문 세트로 맞춘다. 지금은 문헌값과 샘플
      문서로만 정했다.
- [ ] 워터마크·반복 머리 요소가 `drop`되지 않고 남는 페이지가 있다. 규칙 필터는 쓰지 않기로 했으므로
      (method.md) 모델이 보는 맥락과 프롬프트로 줄인다.
- [ ] 진행 표시의 "N / 전체"는 그래프에 넣은 문서 수다. 읽기는 병렬이라, 앞 순서의 긴 문서가
      끝날 때까지 숫자가 멈춰 보인다. 읽은 수를 따로 보일지 정한다.
- [ ] 구절 수를 바꾸면 확인 없이 다시 묻는다. 답변의 인용 칩이 근거 구절로 이동하지 않는다.
